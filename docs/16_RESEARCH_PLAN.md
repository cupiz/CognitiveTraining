# 16 — Research & Validation Plan

## Purpose

The platform's technical scoring system is not automatically a scientifically validated cognitive assessment. Validation is a separate workstream.

## Questions

Q1. Are task metrics reliable across repeated sessions?
Q2. Are different games intended to measure the same construct sufficiently related?
Q3. Do game metrics converge with established measures?
Q4. Does adaptive difficulty estimate a stable task-specific ability?
Q5. Does training produce improvement beyond practice effects?

## Study phases

### Phase A — Measurement quality
- repeated measurements
- estimate test-retest reliability
- inspect floor/ceiling effects
- inspect device effects

### Phase B — Convergent validity
Compare task families with established measures administered under proper protocol.

### Phase C — Normative modeling
Collect a sufficiently broad sample, predefine methods, and validate on held-out data.

### Phase D — Training efficacy
Randomized controlled design where appropriate.
Consider:
- active control
- passive control
- pre-registration
- blinded analysis
- primary outcomes
- multiple-comparison correction
- follow-up

## Important interpretation

Improvement on a trained task can be:
- task-specific learning
- strategy learning
- interface familiarity
- genuine broader improvement

The platform should not conflate these.

## Research data governance

- consent
- de-identification/pseudonymization
- restricted access
- analysis plan
- retention
- publication policy
- conflict-of-interest disclosure
